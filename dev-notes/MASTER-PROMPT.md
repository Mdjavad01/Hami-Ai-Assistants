# MASTER-PROMPT — دستور اجرای خودکار چندساعته (مرجع دائمی)

> این فایل متن کامل مستر پرامپت کاربر + ضمیمه‌ی ادامه‌ی اجرا را نگه می‌دارد تا هر جلسه با «ادامه از PROGRESS.md» بتواند قواعد، دامنه و ترتیب دسته‌ها را بخواند. **تغییر ندهید** مگر با دستور صریح کاربر.

## ضمیمه‌ی ادامه‌ی اجرا (۲۰۲۶-۱۰-۱۳، جلسه‌ی دوم)

وضعیت: دسته‌های ۰، A، B کامل و تگ‌خورده‌اند (`before-autonomous-run`, `after-autobatch-A`, `after-autobatch-B`). آن‌ها تکرار نشوند. اول بخوان: PROGRESS.md، BACKLOG.md، DECISIONS.md، BATCH-C-PLAN.md.

تصمیم‌های تأییدشده‌ی کاربر برای BACKLOG (ثبت‌شده در DECISIONS.md):
- **BL-02:** معیار AGENTS.md (min+gzip؛ JS≤8KB، CSS≤4KB) معتبر است؛ README باید با آن و اعداد اندازه‌گیری‌شده یکی شود (دسته I).
- **BL-04:** UI برای export/import/reset در تب پیشرفته اضافه شود، کوچک و بدون jQuery: export (دانلود JSON بدون کلید API و رمزها)، import با انتخاب فایل و تأیید، reset با تأیید دوباره (مثلاً تایپ کلمه‌ی «بازنشانی»)؛ هر دو قبلش snapshot می‌گیرند و پیام فارسی نتیجه و راه بازگردانی را نشان می‌دهد؛ همه با nonce + capability. تست: Playwright برای هر سه + رد دسترسی بدون capability. **به‌عنوان دسته A2، بعد از C.**
- **BL-01:** ممیزی CSS باید صفر شود؛ در C حل شود.

ترتیب جدید (هر خط یک دسته، با همان روش/تست/commit/tag):
1. **C1** — فلوی تولید محتوای محصول: P3 (دکمه غیرفعال + «در حال ساخت…» + قفل سمت سرور)، P5 (پیام فارسی timeout/504/پروکسی/پاسخ نامعتبر)، P4 (اعمال idempotent). ماک برای کندی/خطا گسترش یابد.
2. **C2** — P2، P6، P7، P8، P9 + حل BL-01. دروازه: pc-e2e همه سبز + چک تازه برای هر مورد.
3. **A2** — UI خروجی/ورودی/بازنشانی (بالا).
4. **G** — امنیت: G1 (SSRF/IPv6/mapped/دسیمال/هگز/اکتال/DNS خصوصی)، G2 (پاک‌سازی نام محصول قبل از context)، G3 (خروجی پاسخ مدل و مصرف‌کننده‌ها)، G4 (فقط گزارش). تست G1 ماتریسی × allow_localhost؛ e2e با allow_localhost=1 سبز بماند.
5. **E** — M9 با dump جدا و تست ارتقا از نسخه‌ی قبلی و از v1.
6. **F** — S1 شورتکد جست‌وجو.
7. **D** — M5–M8.
8. **H** — بازبینی کامل منطق (AUDIT-FULL.md) + رفع فقط موارد پرشدت/کم‌ریسک.
9. **I** — مستندات (README، docs.md، SPEC-ACTUAL.md، «درس‌های ثبت‌شده» در AGENTS.md، PROGRESS.md، audit.txt، .distignore).
10. **J** — پاک‌سازی نهایی و tag `after-autonomous-run`.

**قاعده‌ی تکمیلی اثبات:** تست «قبل از رفع» باید رفتار غلط واقعی را نشان بدهد (خروجی/وضعیت غلط)، نه فقط fatal متد تعریف‌نشده، مگر اینکه رفع یک متد جدید باشد. در هر دسته‌ی جدید بنویسه شود.

**سیاست نشست:** تا جایی که کانتکست اجازه می‌دهد پیش برو؛ فقط در نقطه‌ی تمیز (کار commit‌شده، تست‌ها سبز) بایست، PROGRESS.md را کامل کن و دسته‌ی بعدی را بنویس. پیشنهاد: هر جلسه یک یا دو دسته.

## متن اصلی مستر پرامپت (حرفه‌ی ۱ تا ۴)

**نقش:** مهندس ارشد وردپرس/ووکامرس و بازبین مستقل پروژه‌ی Hami AI Assistant. تأیید صریح کاربر برای تمام دسته‌های فهرست‌شده؛ قاعده‌ی «بدون تأیید مرحله‌ی بعد را شروع نکن» فقط برای این دسته‌ها لغو است. سایر قواعد AGENTS.md کامل برقرارند (فقط فارسی، PHP 7.4، تغییر کوچک و هدفمند، minify فقط با tools/minify.mjs، نام‌گذاری CSS، ماژول خاموش = صفر هزینه، گزارش بدون ادعای دروغ).

### ۰) خطوط قرمز (نقض هرکدام = توقف فوری)
1. sks: هیچ خواندن یا نوشتنی. فقط haai-test.
2. هیچ بخشی از صفر بازنویسی نشود. بزرگ‌تر از اصلاح نقطه‌ای/بازآرایی کوچک با رفتار ثابت → فقط BACKLOG.md با طرح و ریسک.
3. هیچ کلید API، گذرواژه یا توکنی در لاگ، پاسخ، commit یا فایل md چاپ نشود (ماسک).
4. تغییر اسکیمای DB فقط با مهاجرت نسخه‌دار + تست ارتقا از نسخه‌ی قبل و از v1 + mysqldump پیشین. DROP/TRUNCATE فقط روی جدول‌های تست و فقط در dev-tests.
5. هر تغییر در مسیر دسترسی/امنیتی (nonce، capability، is_url_safe، sanitize/escape) باید تست رد/قبول جدا داشته باشد.
6. وابستگی جدید، فریم‌ورک، jQuery، فونت یا درخواست خارجی اضافه نشود. ویژگی PHP 8 ممنوع.
7. هر چیز خارج از دامنه‌ی دسته‌ی جاری → فقط BACKLOG.md (شناسه، فایل:خط، شرح کوتاه)، رفع نشود.
8. تصمیم محصولی مبهم → محافظه‌کارانه‌ترین گزینه + دلیل در DECISIONS.md؛ نایست.

### ۱) روش کار برای هر دسته
a) خواندن فایل‌های مرتبط؛ طرح ۳–۶ خطی در PROGRESS.md.
b) تغییر کوچک → `php -l` همه فایل‌ها → همه سوئیت‌ها → `diagnose()` واقعی → برای UI/فلو تست Playwright روی haai-test (pc-e2e.cjs الگو؛ هر تست در dev-tests).
c) هر دسته یک تست رگرسیون تازه که قبل از رفع شکست می‌خورد و بعد سبز می‌شود (قبل/بعد ثبت شود).
d) git commit کوچک؛ پایان دسته tag `after-batch-<حرف>` (در این اجرا `after-autobatch-<حرف>`، چون `after-batch-A` از قبل وجود داشت).
e) PROGRESS.md با ۳–۶ خط به‌روز شود.
f) سیاست شکست: تست سبزنبشده بعد از ۲ تلاش → revert/reset به tag قبلی همان دسته، علت و شواهد در BACKLOG.md، ادامه‌ی دسته مستقل بعدی. **هرگز تست را برای سبز شدن سست نکن.**
g) ادعای «تست‌شد» فقط برای آنچه در اجرای واقعی/مرورگر دیده شده؛ حضور مارکر در HTML = «فقط خوانده شد»؛ موارد نیازمند کلید واقعی AI = «تست نشد».
h) حافظه/لیمیت: توقف در نقطه‌ی تمیز با PROGRESS.md کامل.

### ۲) پیش‌نیاز (دسته صفر) — انجام شد
git تمیز، tag `before-autonomous-run`، mysqldump تازه در C:\xampp\backups، خط پایه (php -l + سوئیت‌ها + diagnose + pc-e2e). بنچ روی allow_localhost=1. قبل از هر دسته دیتابیسی (E) یک dump جدا.

### ۳) دسته‌ها (شرح کامل هر دسته در پیام اصلی؛ خلاصه‌ی ثابت)
- **A** پایداری تنظیمات: snapshot تک‌نسخه‌ای قبل reset/import (autoload=no، برچسب زمان) + اکشن بازگردانی در تب پیشرفته؛ کلید/رمز همان‌طور رمز بمانند. ✅ انجام.
- **B** وابستگی ووکامرس (M3+M4): منبع حقیقت یکی؛ خفتگی ماژول بدون Woo و حفظ فلگ روشن؛ پیام/کلید غیرفعال؛ activate/deactivate/uninstall بدون fatal. ✅ انجام.
- **C** فلوی کامل UX محتوای محصول: P3 قفل/دکمه، P5 پیام‌های خطا، P4 اعمال idempotent، P2 ترک صفحه/تأیید، P6 یکی‌بودن FAQ پیش‌نمایش و نهایی، P7 بَج ناقص+tooltip، P8 aria-live/فوکوس، P9 کیبورد تب‌ها. (C1/C2 بالا)
- **D** صف و ماژول‌ها: M5 last_error جاب‌ها (ماسک) + دکمه پاک‌سازی شکست‌ها؛ M6 ترجمه وضعیت کمپین؛ M7 ستون آخرین اجرا/خطا و وضعیت واقعی؛ M8 یادداشت «از مسیر چت تغذیه می‌شود».
- **E** M9: حذف هزینه ثابت DB هر درخواست (SHOW TABLES در درخواست بازدیدکننده صفر)؛ تست نصب تازه/ارتقا/ماژول جدید/حذف جدول/اندازه‌گیری با haai-observer.
- **F** S1: شورتکد [haai_search] با assets/js/search.js (ES5، بدون jQuery، ≤۲KB min+gzip، فقط در صفحه شورتکد)، دیبانس، POST به endpoint موجود، textContent، حالت خالی/خطای فارسی، aria، رفع docblock، تست Playwright، حفظ محدودیت نرخ.
- **G** امنیت: G1 SSRF در is_url_safe (IPv6/bracket/mapped/ULA/link-local/0.0.0.0/دسیمال-هگز-اکتال/localhost/DNS خصوصی؛ allow_localhost فقط صریح؛ ریدایرکت بسته)؛ G2 تزریق پرامپت از نام محصول؛ G3 sanitize پاسخ مدل + escape همه مصرف‌کننده‌ها؛ G4 فقط گزارش endpoint/لاگ/uninstall در AUDIT-FULL.md.
- **H** بازبینی کامل منطق همه ماژول‌ها و هسته → dev-notes/AUDIT-FULL.md با جدول شناسه|حوزه|نوع|شدت|فایل:خط|علت|اثر|شواهد|ریسک|پیشنهاد؛ فقط رفع کم‌ریسک پرشدت با تست.
- **I** مستندات: SPEC-ACTUAL.md، README (۱۱ ماژول واقعی، سقف‌ها فقط با عدد اندازه‌گیری‌شده min+gzip، «صفر کوئری» فقط مطابق نتیجه E)، docs.md با اعداد اندازه‌گیری‌شده، AGENTS.md فقط بخش «درس‌های ثبت‌شده»، PROGRESS.md، audit.txt تازه، .distignore کامل.
- **J** پاک‌سازی: حذف کاربر haai_probe، فایل‌های موقت، بازگرداندن بنچ به پایه ({chatbot, product-content}، provider خالی)، اجرای نهایی همه تست‌ها + اندازه‌گیری، tag `after-autonomous-run`، mysqldump نهایی.

### ۴) گزارش
در طول کار هر دسته در REPORT-AUTONOMOUS.md (فایل:خط، قبل/بعد، شواهد، تست‌شد/فقط خوانده/تست نشد). پایان: پاسخ ≤۶۰ خط — جدول دسته‌ها، commit/tagها، چک‌های قبل/بعد، «تست نشد»ها، BACKLOG/DECISIONS، کارهای دستی کاربر، پیشنهاد بعدی.
