# Hami AI Assistant

دستیار هوشمند ماژولار برای وردپرس و ووکامرس: چت‌بات فروش، تولید محتوای سئو، مقاله‌نویس با تحقیق خودکار بازار، پنل پیشنهاد کلمه کلیدی، اتوپایلوت، باشگاه لید، مذاکره‌گر تخفیف، کامنت‌گذار هوشمند، جست‌وجوی معنایی، خبرساز، مقاله از ویدیو و صفحات برنامه‌محور — یازده ماژول در یک افزونه، با هسته‌ی مشترک و ماژول‌های جداگانه.

- **سبک:** بدون jQuery، بدون فریم‌ورک، بدون فونت خارجی، بدون درخواست به سرویس‌های ثالث.
- **سازگار:** PHP 7.4+ و وردپرس 5.8+؛ کاملاً راست‌به‌چپ و فارسی.
- **امن:** کلید API فقط سمت سرور؛ بدون nonce در HTML کش‌شده؛ Sanitize/Escape کامل.
- **هاست ایرانی:** کش اختصاصی، پاکسازی تنبل، تایم‌اوت قابل تنظیم، پروکسی و رله.
- **ماژولار:** هر قابلیت یک ماژول جداگانه است؛ ماژول خاموش = فایل لود نشده، هوک ثبت نشده.

## نصب

1. بسته را بسازید (یا از فایل آماده‌ی `hami-ai-assistant-2.1.7.zip` استفاده کنید — دستور ساختش در `docs.md` بخش 15.5): با پوشه‌ی میانی `hami-ai-assistant/`.
2. **فقط همان ZIP را آپلود کنید**: پیشخوان ← افزونه‌ها ← «افزونه‌ی جدید» ← بارگذاری افزونه ← Choose file. چیز دیگری لازم نیست: نه `dev-tests/`، نه `dev-notes/`، نه `docs.md`/`README.md`/`AGENTS.md`/`audit.txt`، نه `tools/`.
3. اگر از FTP/SSH می‌روید، همان zip را باز کنید تا پوشه‌ی `hami-ai-assistant` در `wp-content/plugins/` ساخته شود، یا با WP-CLI:

```bash
wp plugin install hami-ai-assistant-2.0.0.zip --force --activate
wp eval 'print_r(Haa_Settings::diagnose());'   # باید Array ( ) خالی باشد
```

4. افزونه را فعال کنید. جدول‌های اختصاصی در همان فعال‌سازی ساخته می‌شوند.
5. از منوی **Hami AI** وارد پنل شوید و تب **ارائه‌دهنده AI** را تنظیم کنید.
6. در تب **ماژول‌ها** ماژول‌های مورد نیاز را روشن کنید.

### مهاجرت از Hami AI Chatbot (نسخه ۱)

اگر نسخه‌ی ۱ (Hami AI Chatbot) نصب است، نگران نباشید: با فعال‌سازی نسخه‌ی ۲، مهاجرت به‌صورت خودکار انجام می‌شود — تنظیمات، نالج‌بیس و کلید API منتقل می‌شوند. کافی است نسخه‌ی قدیمی را غیرفعال و نسخه‌ی جدید را فعال کنید.

## راهنمای تب‌ها

### ۱) عمومی

- **فعال:** کلید اصلی روشن/خاموش. وقتی خاموش است، هیچ فایلی و هیچ کوئری دیتابیس اضافه‌ای اجرا نمی‌شود.
- **حالت نمایش:** شورتکد / شناور / هر دو.
- **موقعیت شناور:** سمت، فاصله از پایین و از کنار (پیکسل).
- **شرایط نمایش:** دستگاه، نوع محتوا، صفحات مجاز/ممنوع، نقش کاربر.

### ۲) ارائه‌دهنده AI

سه Adapter واقعی و ده‌ها پیش‌فرض از پیش تعریف‌شده:

| Adapter | سرویس‌ها |
|---|---|
| سازگار با OpenAI | OpenAI، OpenRouter، xAI Grok، DeepSeek، Qwen، Mistral، Groq، Ollama و هر سرویس سفارشی |
| Google Gemini | Google Gemini |
| Anthropic Claude | Anthropic Claude |

- **Base URL قابل ویرایش است** — برای رله، Cloudflare Worker یا پروکسی داخلی فقط آدرس را عوض کنید.
- **تست اتصال** مقادیر همان لحظه را (حتی ذخیره‌نشده) بررسی می‌کند و خطای قابل‌فهم فارسی برمی‌گرداند.
- **کلید API** با AES-256-CBC رمزنگاری و فقط سمت سرور استفاده می‌شود.

### ۳) ظاهر

رنگ‌ها، فونت، اندازه فونت، گردی گوشه، اندازه دکمه، آیکون آپلودی، متن خوش‌آمد و باکس CSS سفارشی — همه با پیش‌نمایش زنده.

فونت پیش‌فرض **فونت سیستم** است. برای فونت دلخواه، فایل WOFF2 را با یکی از این نام‌ها در `assets/fonts/` بگذارید:

```
Vazirmatn-Regular.woff2   → وزیرمتن
IRANSans.woff2            → ایران‌سنس
Dana-Regular.woff2        → دانا
YekanBakh-Regular.woff2   → یکان‌بخ
```

اگر فایل وجود نداشته باشد، افزونه بی‌سروصدا به فونت سیستم برمی‌گردد و **هیچ درخواست 404 ایجاد نمی‌کند**.

### ۴) رفتار چت

- **System Prompt:** شخصیت و قواعد پاسخ‌دهی.
- **تاریخچه:** حداکثر تعداد پیام ارسالی به مدل.
- **سوالات پیشنهادی:** هر سطر یک سوال، حداکثر ۶ مورد.
- **ساعت کاری:** با فعال‌سازی، خارج از بازه پیام آفلاین نمایش داده می‌شود (بازه‌های شبانه هم پشتیبانی می‌شود).
- **جمع‌آوری لید:** با رضایت کاربر، نام و شماره موبایل از چت گرفته می‌شود.

### ۵) محتوا

- **زبان، لحن، طول، مخاطب پیش‌فرض:** برای تولید محتوای محصول، مقاله‌نویس و اتوپایلوت. پنج لحن، هرکدام با جمله‌ی نمونه‌ی خودش؛ طول به «چند کلمه» بیان می‌شود، نه عدد خام.
- **درج لینک داخلی + تعدادش:** لینک فقط از ایندکس و فقط اگر واقعاً مرتبط باشد؛ اگر نبود، بلوک ساخته نمی‌شود.
- **درج قیمت و موجودی در متن:** پیش‌فرض **خاموش** — نه قیمت و موجودی به مدل داده می‌شود، نه در متن/FAQ/عنوان سئو می‌آید؛ چون با تغییر قیمتِ فروشگاه، متن قدیمی می‌شود. اگر روشنش کنید، هشدار کهنگی را کنارش می‌بینید.
- **تولید تصویر:** اندازه، کیفیت و سبک ثابت تصویر شاخص.
- **دسته‌بندی و نویسنده‌ی پیش‌فرض:** برای مقالات اتوپایلوت.
- **سقف توکن روزانه و تعداد پست روزانه:** محافظ بودجه.

### ۶) پیشرفته

- **محدودیت نرخ، لاگ مکالمات، دسترسی، تشخیص IP واقعی، کش پاسخ** — مانند نسخه‌ی ۱.
- **نالج‌بیس / جست‌وجو:** نوع محتوا، اندازه قطعه، همپوشانی، سقف حجم فایل.
- **برون‌ریزی / درون‌ریزی JSON** (بدون کلید API) و **بازنشانی**.

## تولید محتوا و مقاله‌نویس

### تولید محتوای محصول (ووکامرس)

در صفحه‌ی «محتوای محصول»، محصول را انتخاب (یا دسته‌ای در صف گذاشتن) و «ساخت پیش‌نمایش» را بزنید. افزونه:

1. داده‌ی واقعی محصول را از ووکامرس برمی‌دارد و **تمیز** می‌کند: نام ویژگی و مقدارش رمزگشایی و شناسه‌ی ترم به نام تبدیل می‌شود، قیمت با واحد ارز درست نوشته می‌شود، و متن نمونه/لورم هرگز به مدل داده نمی‌شود.
2. از مدل، خروجی ساختارمند JSON می‌خواهد: `html`، عنوان سئو، توضیح متا، اسلگ، خلاصه، FAQ و **`notes`** (یادداشت بازبینی).
3. هر چیز یادداشت‌مانند را از متن بیرون می‌کشد و در پنل «یادداشت‌های بازبینی» نشان می‌دهد؛ تا آن را نبینید و تیک «یادداشت‌ها را دیدم» را نزنید، «اعمال» انجام نمی‌شود و هیچ یادداشتی وارد صفحه‌ی محصول نخواهد شد.
4. طول را می‌پاید: پاسخ بریده‌شده را یک بار ادامه می‌دهد، متن کوتاه را — فقط اگر داده‌ی کافی باشد (دست‌کم ۸ حقیقت) — یک بار بسط می‌دهد؛ اگر داده کم است، حشو نمی‌سازد و دلیلش را می‌نویسد. سقف انتخاب محصول ~۱۲۰۰ کلمه است (۲۲۰۰ کلمه فقط برای مقاله‌نویس).
5. «کاربرد محصول» را از روی نام حدس نمی‌زند؛ اگر نام با دسته یا ویژگی‌ها نخواند، همان را در یادداشت‌ها گزارش می‌کند (اگر خود دسته‌بندی مبهم باشد هم از آن داستان نمی‌سازد). عبارت مبهمی مثل «احتماللاً/به نظر می‌رسد» که با وجود منع پرامپت در متن بماند، سانسور نمی‌شود ولی در یادداشت‌ها اعلام می‌شود.
6. FAQ فقط از داده‌ی واقعی: سؤال قیمت/موجودی یا پاسخ «احتمالاً/شاید» منتشر نمی‌شود و به یادداشت‌ها می‌نشیند.
7. پیش‌نمایش کامل قابل ویرایش است و با «اعمال روی محصول» در توضیحات، خلاصه، اسلگ و Yoast/RankMath/AIOSEO نوشته می‌شود. تصویر شاخص هم اختیاری است؛ شکست تصویر، متن را خراب نمی‌کند.
8. «مقاله‌های مرتبط» از ایندکس سایت می‌آید با آستانه‌ی ارتباط؛ اگر چیزی مرتبط نبود، برگه‌های هم‌دسته (حداکثر ۳) پیشنهاد می‌شوند و اگر نه، هیچ بلوکی ساخته نمی‌شود — هیچ‌وقت برگه‌ی «درباره ما» یا دموی قالب به‌عنوان مطلب مرتبط نمی‌آید. در عوض برگه‌ای مثل «ورودی و خروجی» یا اسلاگ `about-argan-oil` حذف نمی‌شود؛ سیاهه واژه‌به‌واژه است، نه زیررشته. اگر ایندکس سایت خالی باشد، برگه‌ای که کلیدواژه فقط در **متنشان** هست هم پذیرفته نمی‌شود: تیتر یا اسلگ باید یک واژه‌ی مشترک داشته باشد.
9. یک محصول هم‌زمان از دو جا تولید نمی‌شود: دکمه‌ی دستی و کارِ صف همان قفل را می‌گیرند؛ اگر قفل دست دیگری باشد، کار صف کمی بعد دوباره امتحان می‌شود (به‌جای پرداخت دوباره‌ی هزینه) و پیش‌نمایش موجود خراب نمی‌شود.

### مقاله‌نویس

در صفحه‌ی «مقاله‌نویس»، لیست موضوعات را (هر خط یک موضوع) وارد کنید. هر موضوع به‌صورت دسته‌ای در صف قرار می‌گیرد و یکی‌یکی به پیش‌نویس تبدیل می‌شود. عنوان، ساختار H2/H3 و تصویر شاخص به‌صورت خودکار تولید می‌شوند.

#### پیشنهاد کلمه کلیدی (پنل جدید)

در همین صفحه، موضوع را بنویسید و «پیدا کن» را بزنید: پیشنهادهای واقعی تایپ کاربران گوگل (ساجست)، عنوان نتایج سرویس SERP (در صورت اتصال)، کلیدواژه‌های ذخیره‌شده از تحلیل رقبا و ایده‌های مدل با هم ترکیب، بدون تکرار مرتب و نمایش داده می‌شوند. تیک بزنید تا به‌عنوان موضوع پیشنهادی به برنامه‌ریز اضافه شود.

#### پژوهش هوشمند رقبا (Gemini)

اگر هاست شما نتواند به سایت رقبا یا گوگل وصل شود (خطای «دامنه قابل resolve نیست»)، با ارائه‌دهنده‌ی Gemini تحلیل به‌صورت خودکار با «جستجوی گوگل» خودِ مدل انجام می‌شود: رقیب‌های برتر، سرفصل‌ها و پرسش‌های رایج بازار فارسی استخراج و در همان snapshot ذخیره می‌شود. درخواست‌های مستقیم هم حالا از پراکسی تنظیم‌شده در تب ارائه‌دهنده عبور می‌کنند.

#### مقاله‌های جامع

سقف طول مقاله تا **۵۰۰۰ کلمه** (پیش‌فرض گزینه‌های «جامع ~۳۰۰۰» و «خیلی جامع ~۴۵۰۰» در انتخاب‌های طول) بالا رفته است؛ هر بخش در فراخوان جدا با سقف خروجی بالاتر نوشته می‌شود و اگر خروجی مدل بریده شود، یک بار ادامه‌ی خودکار گرفته می‌شود.

### اتوپایلوت

یک کمپین تعریف کنید: موضوع، مخاطب، تناوب (ساعتی/روزانه/هفتگی) و ساعت اجرا. کران هر ۵ دقیقه بررسی می‌کند و اگر نوبت رسیده باشد، مقاله را می‌سازد — با سقف روزانه توکن و تعداد پست که خودتان تعیین می‌کنید.

## مذاکره‌گر تخفیف

در چت، وقتی مشتری اصرار بر تخفیف می‌کند، ربات در سقفی که تعیین کرده‌اید چانه می‌زند و در صورت توافق یک **کد تخفیف واقعی ووکامرس** صادر می‌کند:

- هر کد هم در جدول اختصاصی افزونه و هم به‌صورت WC_Coupon واقعی ساخته می‌شود — پس اگر افزونه را حذف کنید، کدهای قبلاً صادرشده همچنان کار می‌کنند.
- سقف مطلق تخفیف، سقف هر بازه‌ی زمانی، تعداد دور چانه‌زنی و اعتبار کد همه قابل تنظیم‌اند.
- هر بازدیدکننده در هر بازه فقط تعداد محدودی کد می‌گیرد.

## جست‌وجوی معنایی

ایندکس ترکیبی روی نوشته‌ها، برگه‌ها، محصولات و فایل‌های TXT/MD/DOCX:

- **نرمال‌سازی فارسی** در هر دو سمت (ي→ی، ك→ک، یکسان‌سازی ارقام، نیم‌فاصله، حذف اعراب، Stop Word).
- **BM25** برای بازیابی کلیدواژه‌ای + **امبدینگ** برای بازیابی معنایی (در صورت فعال‌سازی).
- **بازسازی دسته‌ای** با سقف زمانی ۱۲ ثانیه در هر درخواست — مناسب هاست‌های اشتراکی.
- **شورتکد `[haai_search]`** یک کادر جست‌وجوی سبک در هر صفحه‌ای قرار می‌دهد.

> **PDF پشتیبانی نمی‌شود.** فایل PDF را به TXT تبدیل کنید.

| عدم دسترسی مستقیم به سرویس‌های خارجی | Base URL رله/Worker + پروکسی `host:port` با احراز هویت |
| تایم‌اوت ۳۰ ثانیه‌ای | تایم‌اوت قابل تنظیم تا ۱۲۰ ثانیه؛ پیام خطای فارسی |
| WP-Cron قابل‌اعتماد نیست | پاکسازی «تنبل» با احتمال ۲٪ روی درخواست‌های واقعی + صف کارها با موتور یک‌در-میان |
| کش سنگین (LiteSpeed / WP Rocket / Cloudflare) | هیچ nonce در HTML کش‌شده نیست؛ توکن ۱۰ دقیقه‌ای به کوکی HttpOnly گره می‌خورد |
| رم محدود | بازسازی دسته‌ای با سقف ۱۲ ثانیه؛ بدون کتابخانه‌ی PDF |

| `assets/js/chatbot.js` | ۱۵ کیلوبایت | ~۴KB (min+gzip) |

- در صفحاتی که چت ندارند: **صفر** فایل و **صفر** کوئری اضافه.
- در حالت شناور فقط `loader.js` لود می‌شود؛ CSS، HTML و JS اصلی بعد از **اولین کلیک** می‌آیند.
- تنظیمات در **یک option آرایه‌ای با `autoload = no`** ذخیره می‌شود. فقط گیت روشن/خاموش و لیست ماژول‌های فعال (هر دو کوچک) به‌صورت دائم در حافظه‌اند.

## رفع اشکال

| علامت | علت محتمل |
|---|---|
| **«کلید API تنظیم نشده است»** | تب ارائه‌دهنده AI را کامل نکرده‌اید. |
| **«دامنه قابل resolve نیست»** | هاست شما دسترسی مستقیم ندارد. Base URL رله یا پروکسی تنظیم کنید. |
| **401** | کلید اشتباه است یا مدل انتخابی در اکانت شما فعال نیست. |
| **402** | اعتبار اکانت سرویس AI تمام شده است. |
| **توکن چت منقضی شده است** | صفحه را تازه‌سازی کنید. |
| **ماژولی در منو دیده نمی‌شود** | در تب «ماژول‌ها» فعالش کنید. |
| **اتوپایلوت کار نمی‌کند** | سقف توکن/پست روزانه پر است یا WP-Cron کار نمی‌کند. |
| **«اعمال روی محصول» انجام نمی‌شود** | پنل «یادداشت‌های بازبینی» یادداشت باز دارد؛ آن‌ها را بخوانید و تیک «یادداشت‌ها را دیدم» را بزنید. پیش‌نمایش و ویرایش‌هایتان حفظ می‌شود. |
| **متن محصول کوتاه‌تر از انتخاب ماند** | داده‌ی محصول کم است؛ افزونه به‌جای پرکردن با حشو، دلیلش را در یادداشت‌ها نوشته است. |
| **کد تخفیف صادر نشد** | سقف تخفیف بازه‌ی زمانی تمام شده است. |

### پاکسازی دستی

اگر افزونه را حذف کردید ولی جدول‌ها ماند، `uninstall.php` را دستی اجرا کنید:

```sql
DROP TABLE IF EXISTS wp_haai_chunks;
DROP TABLE IF EXISTS wp_haai_cache;
DROP TABLE IF EXISTS wp_haai_logs;
DROP TABLE IF EXISTS wp_haai_rate;
DROP TABLE IF EXISTS wp_haai_usage;
DROP TABLE IF EXISTS wp_haai_queue;
DROP TABLE IF EXISTS wp_haai_sessions;
DROP TABLE IF EXISTS wp_haai_vectors;
DROP TABLE IF EXISTS wp_haai_leads;
DROP TABLE IF EXISTS wp_haai_lead_events;
DROP TABLE IF EXISTS wp_haai_coupons;
DROP TABLE IF EXISTS wp_haai_campaigns;
DROP TABLE IF EXISTS wp_haai_comment_jobs;
DROP TABLE IF EXISTS wp_haai_topics;
DROP TABLE IF EXISTS wp_haai_news_items;
DROP TABLE IF EXISTS wp_haai_prog_items;
DELETE FROM wp_options WHERE option_name IN
  ('hami_ai_assistant','hami_ai_assistant_on','hami_ai_assistant_modules',
   'haai_db_version','haai_migrated','haai_queue_lock','hami_ai_kb_state');
```

این شانزده جدول، همان `Haa_DB::registry()` است؛ اگر جدولی در سایت شما نیست، ماژولش هیچ‌وقت ساخته‌اش نشده.

## امنیت

- کلید API و گذرواژه‌ی پروکسی با AES-256-CBC رمزنگاری و فقط سمت سرور استفاده می‌شوند.
- هیچ رمزی در `HAAI_CONFIG`، HTML کش‌شده یا خروجی JSON وجود ندارد.
- همه‌ی مسیرهای REST دارای `permission_callback`، Honeypot و محدودیت نرخ هستند.
- خروجی ویجت با `esc_html` / `esc_attr` / `wp_kses_post` رندر می‌شود.
- هیچ دیدگاهی بدون تأیید شما منتشر نمی‌شود.
- هیچ یادداشت بازبینی (مثل `[نیاز به داده…]`) وارد صفحه‌ی محصول، FAQ یا متای سئو نمی‌شود: در تولید از متن جدا و در «اعمال» گارد می‌شود.
- محتوای تولیدشده «تضمین‌شده درست» نیست؛ ادعاها علامت می‌خورند و انتشار نهایی تصمیم انسانی است.
- `uninstall.php` همه‌چیز را حذف می‌کند و فقط آیکون/تصاویری را پاک می‌کند که به هیچ نوشته‌ای متصل نیستند.

## توسعه

```bash
php -l hami-ai-assistant.php
php -l includes/*.php
php -l modules/*.php
```

قالب ترجمه را با این دستور به‌روز کنید (از ریشه‌ی افزونه؛ پوشه‌های تست و ابزار بیرون می‌مانند):

```bash
wp i18n make-pot . languages/hami-ai-assistant.pot \
  --exclude="dev-tests,tools,.workbuddy-ai" \
  --package-name="Hami AI Assistant" \
  --headers='{"Report-Msgid-Bugs-To":"https://example.com/hami-ai-assistant","Language-Team":"Persian <fa@example.com>"}'
```

نام کلیدها در `--headers` باید **دقیقاً همان نام canonical** هدر باشد (`Report-Msgid-Bugs-To`, `Language-Team`)؛ با حروف کوچک، مقدار به‌صورت هدر اضافیِ جدید اضافه می‌شود و `Language-Team: LANGUAGE <LL@li.org>` سرِ file می‌ماند. `Language` در .pot نمی‌آید (قالب است، نه ترجمه) و `X-Domain` خودِ ابزار ست می‌کند.

خروجی باید بدون `Warning` تمام شود (هشدار یعنی رشته‌ای جای‌نما دارد ولی کامنت `translators:` ندارد، یا یک msgid دو کامنت متفاوت گرفته). آخرین تولید: **۱۲۷۴ msgid**.

### افزودن ماژول سفارشی

یک کلاس بسازید که `Haa_Module_Interface` را پیاده کند:

```php
final class Haa_Module_Mything implements Haa_Module_Interface {
        public function slug() { return 'mything'; }
        public function label() { return 'ماژول من'; }
        public function description() { return 'توضیح کوتاه.'; }
        public function requires_woocommerce() { return false; }
        public function register() { /* add_action / add_filter */ }
        public function activate() {}
        public function deactivate() {}
}
```

سپس آن را در `Haa_Modules::catalog()` اضافه کنید تا در تب «ماژول‌ها» نمایش داده شود. فایل باید در `modules/class-haa-module-mything.php` باشد.
